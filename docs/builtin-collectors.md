# 内置采集器

Studio 除 Codex 外还带有本机「系统」、GitHub 和 B 站直播采集器。点击主窗口的「管理采集器」进行配置，再将相应卡片加入屏幕布局。

支持多实例的模块会显示「采集实例」。点「新增实例」，填写参数并保存，再启用采集。可以用「改名」给实例取一个便于识别的短名称。回到布局后，从对应模块下添加各实例的组件。停用会保留配置和布局。删除前请先移除该实例的卡片并应用布局。

## 系统

系统采集器在 Studio 运行时自动读取本机指标，卡片包括：

- CPU 当前占用、区间和趋势
- 内存占用及已用/总量
- 系统盘使用率
- 网络下载与上传速率
- 开机时长

## GitHub 仓库

GitHub 采集器默认停用，每 60 秒查询一次。每个实例填写一个 `GITHUB_REPOSITORY`，支持 `owner/repo` 或 `https://github.com/owner/repo`。可选填写 `GITHUB_TOKEN`；配置敏感值后表单只显示是否已配置，不会回显原值。

模块显示开放 PR 数、开放 Issue 数和最近一次 Actions 状态。首次启用时确认 GitHub API 访问授权。请求只发往 `api.github.com`，令牌只放在授权请求头中。公开仓库可以不填写令牌，但会受到 GitHub 匿名 API 限额影响。

## B 站直播

B 站直播采集器默认停用，每 30 秒读取一次公开直播状态。监听三位主播时，保留原有实例，再新增两个实例。每份配置填写一位主播的 `BILIBILI_UID`，保存后启用并确认桌面通知授权。布局中会有三张以实例名称区分的直播卡。

直播卡的第一行显示开播状态，第二行显示 UP 主昵称。开播时状态条为绿色，未开播时使用默认色。首次成功采样只显示当前状态；此后每次开播和下播各通知一次。短暂请求失败会保留上次状态。

桌面通知由操作系统管理；如果系统禁用了 Mado Studio 的通知，需要在系统通知设置中重新允许。B 站公开接口或响应字段可能调整，接口异常时工作区会显示采集错误。

## 配置值的本机存储

采集器变量在 App 本机加密存储。App 自动生成并使用本地密钥，不需要系统凭据库或额外密码。GitHub Token 等敏感字段不会出现在采集器状态、日志或导出项目中。密钥文件和数据文件都由当前用户账户管理；详细保护边界见[采集器变量说明](display-config-model.md#采集器变量)。
