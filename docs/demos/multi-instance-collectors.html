组件库 · 按实例分组
卡片绑定到实例 ID。改配置、停用或删除某个实例时，其余实例的读数和状态不受影响。

开发者：定义一次，批量处理实例

Manifest 声明“允许多实例”、变量与组件；脚本可选实现 collectBatch。框架把同一模块的启用实例打包调用，并要求结果按 instanceId 返回。

1
声明实例策略与变量
变量是每份实例配置，不是模块全局值。旧模块未声明多实例时继续按单实例工作。
2
在 collectBatch 里逐实例读取参数
按实例隔离状态与错误。上游有批量 API 时可合并网络请求；没有时也可在一次脚本运行中逐个请求。
3
用组件键生成实例卡片
组件定义只写一次。宿主生成 instanceId + widgetKey 的稳定 ID，并把每张卡绑定回来源实例。
Manifest 定义→N 个 Instance→collectBatch→N 组结果 / 卡片
批量调度 ≠ 一次 HTTP 请求。脚本可以一次收到 N 个实例，但是否能向服务端合成一个请求，由该 API 是否支持决定；结果仍逐实例返回。
manifest.json + index.mjs
// manifest.json（节选）
{
  "moduleId": "bilibili",
  "instances": {
    "mode": "multiple",
    "batch": true
  },
  "settings": {
    "BILIBILI_UID": {
      "label": "主播 UID",
      "default": "",
      "description": "填写 B 站用户空间 UID，应用会读取公开的直播间状态。",
      "required": true
    }
  },
  "outputs": {
    "liveStatus": {
      "valueType": "state",
      "detailKeys": [
        "title",
        "url"
      ],
      "stateKeys": [
        "live",
        "offline"
      ]
    }
  }
}

// index.mjs
import { defineModule } from '@mado/sdk'
import { collectBilibili } from './client.mjs'

export default defineModule({
  async collect(settings, context) {
    return collectBilibili(settings, context, context.state)
  },
  async collectBatch(instances, context) {
    const results = []
    for (const { id, settings, state } of instances) {
      try {
        const result = await collectBilibili(settings, context.forInstance(id), state)
        results.push({ instanceId: id, ...result })
      } catch (error) {
        results.push({ instanceId: id, error: error.message })
      }
    }
    return { results }
  },
})
参数、权限和输出的完整定义见采集器模块文档。
