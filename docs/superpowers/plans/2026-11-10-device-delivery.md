# 独立采集与 USB 实体屏实施计划

**目标**：独立 MJS 插件实际采集，Studio 定时通过 USB 发送全页面读数，设备依照原型渲染。Wi-Fi 与 BLE 保留通道扩展接口。

**依据**：[总体设计](../../design.md)、[协议](../../display-protocol.md)、[原型视觉与动效](../../display-ui.md)、[固件资源](../../firmware-resources.md)。

- [x] 以现有测试为基线，锁定 ESP-IDF、板级 GPIO、LVGL 和构建资源。识别实板芯片和 Flash，先保存原始固件。
- [x] 用同一批输入验证 Codex、电脑与用户 MJS 的执行。迁移专用采集逻辑，提供独立入口与通用宿主接口，保留旧配置和卡片 ID。
- [x] 建立 USB UTF-8 单行 JSON 通道，限制消息为 65536 字节，单独输出固件日志。执行协议的握手、校时、配置确认、全量数据、切页、设置、状态、心跳与重试。
- [x] 保持配置、读数及状态通知的数据边界。验证错误帧原子拒绝，重试不重复播放，断线保留读数，重启仅恢复持久配置。
- [ ] 用同一视觉规格补齐 Studio 与 LVGL。逐项验收六类卡片、四种尺寸、五页、主题、滚动与渐隐、计数与逐位滚动、状态提醒、连接与供电画面。
- [ ] 生成完整 CN 字库及 IconPark 资源。测量冷出字、PSRAM、Flash 容量和滚动时的刷新时间。
- [x] 运行 App 的前端和 Rust 检查，构建固件，在 V1.0 实板验证从真实采集到连续更新的闭环，以及 USB 断开重连和重启恢复。


已通过 22 项前端测试、46 项 Rust 单测、2 项 CLI 集成测试、应用和固件构建。自带 MJS 插件均完成独立实采。USB 实板通过 5 页 40 卡和 36,280 字节读数压力测试，以及重启恢复。Studio 已收到实板对真实 Codex 读数的确认，JTAG 读回验证了 RGB565 画面。整套物理屏色彩与动效校准、纯电池场景和长时间性能测量仍保留在验收清单。
