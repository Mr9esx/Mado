# 采集器变量、GitHub 与 B 站设计

## 目标

扩展现有采集器模型，让作者能声明要向用户收集的配置变量，并由 Studio 生成配置表单。变量值保存在 App 自己的本机采集器数据存储中并加密，不调用 macOS Keychain、Windows Credential Manager 或 Linux Secret Service，也不要求用户输入 App 密码。基于此能力，扩展系统状态，并新增 GitHub 仓库状态和 B 站主播开播状态采集器。

## 当前结构

- Codex 与系统状态以 MJS 内置模块实现，和用户采集器共用 QuickJS 运行器、调度、授权代理及输出契约。
- 模块参数声明位于 `Definition.settings`；用户绑定的路径、程序和其他实例数据当前也保存在 `collectors.json` 的实例 `settings` 字段。正式采集接收 `collect(settings, context)`。
- 系统授权由 Rust `sysinfo` 返回 CPU、内存和开机时长。
- `state` 读数支持设备状态卡的一次性提醒动画；目前没有桌面通知通道。
- 页面卡片渲染支持 metric、progress、state、chart、trend、range 与倒计时。

## 决策

### 1. 变量声明与脚本读取

扩展当前 `settings` 定义，保持旧模块有效。新变量使用全大写加下划线的键名，并声明中文名称、描述、是否必填和是否敏感。例如：

```json
{
  "settings": {
    "GITHUB_REPOSITORY": {
      "label": "GitHub 仓库",
      "description": "仓库标识，格式为 owner/repo。",
      "required": true
    },
    "GITHUB_TOKEN": {
      "label": "GitHub 令牌",
      "description": "私有仓库需要；公开仓库可留空。",
      "required": false,
      "secret": true
    }
  }
}
```

采集器仍通过现有第一个参数读取变量，例如 `collect(settings, context)` 中访问 `settings.GITHUB_TOKEN`。新变量名须匹配 `[A-Z][A-Z0-9_]*`；历史小写 `settings` 键继续兼容。作者工具提供变量名和配置字段的补全。

### 2. 自动配置表单

在采集器工作区为已发布模块提供「配置变量」入口，按清单的 `settings` 定义生成表单。表单显示中文名称和描述，必填值校验；敏感值使用密码输入，保存后不回显原值，只显示已配置状态。用户编辑新草稿时可预览定义但不能覆盖正式实例配置。

按模块实例保存变量。修改后立即触发一次采集；模块停用时仍允许配置。离线试跑继续由 fixture 提供 settings，不访问用户存储。导入/导出只携带变量定义，不携带实例值。

### 3. 本机加密存储

变量密文保存在 App 自己的采集器本机存储中。新值在持久化前使用 AES-256-GCM 加密，每个值使用随机 nonce 和带版本的密文封装；密钥由 App 首次运行时生成，放在 App 配置目录的独立密钥文件。App 启动和采集时自动解密，用户不需要密码或解锁步骤。密钥文件尽可能限制为当前用户可读写权限。

数据库/配置文件单独泄漏时，变量不可直接明文读取。因为用户明确选择不使用系统凭据库或 App 密码，密钥也保存在本机；同一用户进程能够读取密钥，因此该设计用于本机静态数据加密，不声称抵御当前用户权限下的恶意程序。旧实例中的明文变量值在成功加载并保存时迁移为密文。状态查询和日志不得返回变量明文。缺失或损坏密钥时明确报错，不覆盖密文或静默生成新密钥。

### 4. 系统状态扩展

系统模块标题缩短为「系统」，新增指标：CPU 当前占用、内存已用与总量、系统卷已用比例、网络上下行速率。保留开机时长及现有 CPU 历史图、趋势和区间卡。显示标签尽量不超过四个汉字；容量使用易读单位。采样由 Rust 原生宿主提供跨平台指标，MJS 模块只负责转换读数。网络速率基于累计字节差值计算，首次样本或计数器重置时为空读数。系统卷选取规则需跨平台一致，并以各平台系统卷或根卷为准。

### 5. GitHub 内置采集器

模块名显示为 `GitHub`，用 `GITHUB_REPOSITORY` 配置 `owner/repo`，`GITHUB_TOKEN` 为可选敏感变量。读取 GitHub REST API 的公开仓库信息，返回开放 PR 数、开放 Issue 数和最近一次 Actions workflow 状态。每个 HTTP 资源仅允许 GET 且固定到 `api.github.com`；令牌仅通过 Authorization 请求头发送，不写日志或读数。默认采样间隔为 60 秒，模块默认停用，配置后可启用。

组件标签采用短文案：`PR数`、`Issue`、`CI状态`。仓库不存在、令牌权限不足、API 限流及网络错误通过明确的采集错误状态报告，不将错误响应当成零值。查询 Issue 时排除 pull request 项。

### 6. B 站开播采集器

模块名显示为「B站」，用必填变量 `BILIBILI_UID` 指定主播 UID。按 30 秒采样间隔查询 B 站公开直播状态接口，并显示一个 `开播` 状态卡；开播状态附带直播标题和房间链接。第一轮成功采样只记录初始状态；只有后续从未开播变成开播时才请求通知。短暂查询失败不重置上一次有效状态，避免错误触发。

同一次开播转换同时触发状态卡一次性提醒与本机桌面通知。通知标题使用主播名，内容使用直播标题和房间链接。App 未获得系统通知权限或平台无通知服务时保留状态卡，记录可见错误但不让采集失败。停用后重新启用会重新初始化状态，不补发已经开播的旧通知。

B 站接口不是稳定的公开开发者契约；解析器隔离在单独模块并用 fixture 覆盖典型响应和错误码，以便接口变化时替换。

### 7. 内置身份与兼容

为 `github` 与 `bilibili` 保留内置模块 ID，禁止用户导入同 ID 覆盖。已有 `codex` 与 `system` 模块 ID、输出和卡片 ID 保持不变；已有布局继续有效。系统组件新增为新 ID，不移动或删除既有卡片。所有内置模块继续使用相同 MJS SDK 与调度器。

## 失败处理与隐私

- 必填变量未配置时，表单标示缺失项并阻止启用采集；不以空字符串发送请求。
- 用户可清空或替换变量；删除模块实例时同步清除其本地变量密文。
- 网络采集超时与限流保留框架现有过期读数规则；B 站的短时失败不触发开播通知。
- GitHub Token 只在 HTTP 请求执行期间进入内存；脚本日志过滤配置中标记为 `secret` 的值。
- App 日志、错误文本、目录导出和 UI 状态不得包含敏感变量值。

## 验证

- Rust：变量名/必填校验、密文往返、nonce 唯一性、旧明文配置迁移、密钥损坏保护、状态对象不泄露变量、删除实例清理密文。
- MJS：GitHub fixture 的 PR/Issue/Actions 解析、令牌请求头、错误与限流处理；B 站开播转换、首次采样和失败状态行为；系统单位换算及网络速率计数器重置。
- UI：按声明生成字段、描述与必填提示、敏感字段遮蔽和清空替换、配置保存后刷新状态。
- 通知：验证开播变化仅通知一次，并覆盖权限未授予与无通知服务的回退。
- 完成后运行现有测试、前端构建与 Rust 测试。跨平台兼容由 Windows/macOS/Linux CI 构建覆盖；当前本机不能替代其他平台的实机验证。

## 范围外

- 不新增系统托盘或全局通知规则编辑器。
- 不实现 B 站直播弹幕、观看人数或直播内容抓取。
- 不新增组件渲染种类；新采集器使用现有组件类型。
- 不迁移 Codex 登录方式，也不改变实体屏蓝牙的平台限制。
